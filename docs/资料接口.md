# 资料服务接口

相同片段路径在窗口推进后可能成为 410；尚未发布的片段返回 404，`/clock` 随同一操作推进。普通预览只列机位，不展开时间线或领取媒体。

清单使用 DASH 命名空间。MP4 样例只保留资料领取需要的容器头，不提供可播放视频；接收端保存并校验原字节，不执行解码、不做转码。`/clock` 提供受控来源时钟，片段可用性以该时钟及 MPD 共同说明；时钟由场景夹具的路由给出，来源服务不硬编码时钟值。

本地服务的资料入口为 `/live.mpd`。`fixtures/ordinary.json` 记录当前可预览的资料；`fixtures/transition.json` 保存资料源连续两个发布日期；`fixtures/cameras.json` 是双机位（其中一个机位阶段性失联并过期）；`fixtures/gap.json` 含两个 Period 之间的真实空档；`fixtures/revision.json` 演示同一地址在清单刷新后换内容；`fixtures/future.json` 含固定次数声明但尚未发布的片段。调用 `POST /control` 并传入 `{"action":"advance"}` 推进发布日期，`inspect` 返回实际请求记录，`reset` 恢复本地源；控制入口不属于远端标准协议。来源分段、延迟和断连均可用场景条目的 `chunks`、`delayMs`、`disconnect` 配置，不需要依赖实际网络故障。

## 持续归档语义

归档器按选中的 Representation 保留初始化资料（SegmentTemplate 的 initialization）与媒体片段，原字节内容摘要寻址存入原件目录，不做任何转码。

- **可用窗口跟随来源**：每轮核对先取 MPD 与 `/clock`，按 `availabilityStartTime`、`timeShiftBufferDepth` 与来源时钟算出直播边缘和窗口起点。窗口内的片段才发起媒体请求。
- **SegmentTimeline 重复**：固定次数（`r>=0`，含自身共 `r+1` 次）按声明展开，即使指向未来也保留为“待领”，不提前发请求；`r="-1"` 没有固定次数，只展开到直播边缘，受条目数上限保护，绝不排出无限多的未来请求。
- **Period 空档**：上一个 Period 最后片段结束到下一个 Period 首个片段开始之间的真实空档如实登记在状态 `gaps` 中；零或负长度的衔接不是空档，也不会被补成零长度片段。
- **片段身份与时间线绑定**：每张接收凭据的 `context` 记录采用时的清单地址与 `publishTime`、Period/Representation、SegmentTemplate 时间戳、媒体地址与实际响应地址。清单刷新改地址、或同一地址换内容时，窗口内已收妥片段会重新核对；内容摘要变化时旧版本在 `revisions` 留痕，新旧原件都可凭摘要回读。
- **暂停与恢复**：归档状态（含每个片段的 received/pending/expired 状态、收妥时段、过期时段、空档、初始化资料、机位错误）原子写入 `archive/archive-state.json`。暂停后重新打开同一目录即可恢复，资料员能区分哪些时段确实收妥、哪些已过期拿不到、哪些仍在等待。
- **机位隔离**：每个 Representation 独立核对，单个机位失联（网络错误、断连）只把错误记在该机位名下，不影响其他已授权机位继续接收。

原件目录采用内容摘要寻址，接收凭据独立记录来源、媒体类型和预览结果。单份资料接收不表示来源范围已经读完，也不推断缺失资料的业务含义。
